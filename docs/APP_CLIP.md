# Makonix App Clip — RoomPlan scanning for the Makonix Telegram Mini App

The `Makon3DAppClip` target lets a user scan a room with Apple RoomPlan
**without installing the full Makonix app**. The Makonix Mini App
(`uydoshtech.github.io/makon3d/`, `@makon3d_bot`) creates a scan session on
the uydosh backend, shows the invocation URL as a link/QR, the clip scans +
uploads, and the user returns to Telegram where the finished scan opens in
the gallery viewer.

This target is a product-branded sibling of the UyDosh App Clip — the scan
flow, backend contract, testing setup, and release process are identical, so
**uydosh_mobile/docs/APP_CLIP.md is the reference documentation**. This file
covers only what differs.

```
Makonix Mini App                 Backend                        App Clip
────────────────                 ───────                        ────────
create scan session ─────────▶  POST /makon3d/scan-sessions
                    ◀─────────  { scanSessionId, invocationUrl, expiresAt }
QR / openLink(invocationUrl) ────────────────────────────────▶ launch
                                GET /scan-sessions/{id}  ◀──── validate
                                                               RoomPlan scan
                                POST .../uploads         ◀──── upload URLs
                                (PUT files)              ◀──── upload USDZ/JSON
                                POST .../complete        ◀──── mark done
                                → Makon3dScanService.uploadScan
                                  (USDZ → GLB → metrics → GIF,
                                   creates makon3d_scans row)
read start_param=scan_{id} ◀─────────────────────────────────  t.me return link
```

## Identity (vs the UyDosh clip)

| | UyDosh clip | Makonix clip |
|---|---|---|
| Target / sources | `UyDoshAppClip` (uydosh_mobile) | `Makon3DAppClip` (this repo) |
| Bundle ID | `com.uydosh.app.Clip` | `com.makon3d.app.Clip` (parent `com.makon3d.app`) |
| Invocation host | `scan.uydosh.com` | `scan.makon3d.uydosh.com` |
| Session target | `listing` | `makon3d` |
| Return deep link | `t.me/uydosh_bot/app` | `t.me/makon3d_bot/app` |
| Team / deployment | D5THR62Q33 / iOS 17.0 | same |

`ios/Shared/` is copied from uydosh_mobile (pure Swift, no Flutter/CocoaPods
— a Flutter dependency cannot fit the App Clip size budget); only
`Shared/AppClipCore/AppClipConfig.swift` differs (host, bot). When fixing
scan-flow bugs, mirror the change in both repos.

The target, groups, and shared scheme are generated by
`ios/scripts/add_app_clip_target.rb` (re-runnable; picks up new files under
`ios/Shared` and `ios/Makon3DAppClip`):

```bash
bundle exec ruby ios/scripts/add_app_clip_target.rb
```

## Backend rollout switch

The backend keeps routing makon3d scan sessions to the **UyDosh** clip
(which is flow-agnostic and handles them fine) until
`MAKON3D_SCAN_CLIP_INVOCATION_BASE=https://scan.makon3d.uydosh.com` is set in
`/etc/uydosh/uydosh.env` — set it only after the manual release checklist
below is complete, and QR/scan links flip to this clip atomically.

Related backend env vars (see uydosh_backend README "Deep links"):
`MAKON3D_APPLE_TEAM_ID` (AASA, defaults to `APPLE_TEAM_ID`) and
`MAKON3D_APPLE_APP_STORE_ID` (Safari App Clip card on the `/s/:token`
fallback page).

## Local testing

Same mechanisms as the UyDosh clip (`_XCAppClipURL`, `SCAN_CLIP_MOCK`,
`SCAN_CLIP_FORCE_SUPPORTED`, `SCAN_CLIP_MOCK_UPLOAD_FAILURES` — all
pre-configured in the shared `Makon3DAppClip` scheme). Command line:

```bash
xcodebuild -project ios/Runner.xcodeproj -scheme Makon3DAppClip \
  -configuration Debug -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO build
```

## Manual release checklist (developer portal / App Store Connect / infra)

1. developer.apple.com ▸ Identifiers: register `com.makon3d.app.Clip` with
   the **App Clip** (On Demand Install Capable) and **Associated Domains**
   capabilities, parent app `com.makon3d.app`.
2. Create an **App Store distribution provisioning profile** for
   `com.makon3d.app.Clip`; base64 it into the
   `IOS_APPCLIP_PROVISION_PROFILE_BASE64` GitHub secret of this repo
   (release-testflight.yml requires it — the clip is embedded in every IPA).
3. Point `scan.makon3d.uydosh.com` DNS at the backend + TLS + proxy. The AASA
   must be reachable at
   `https://scan.makon3d.uydosh.com/.well-known/apple-app-site-association`
   (application/json, no redirects) — the backend already serves it
   host-aware once `MAKON3D_SCAN_CLIP_INVOCATION_BASE` is set.
4. Upload a build; add a Beta App Clip Experience (URL prefix
   `https://scan.makon3d.uydosh.com/s/`) for TestFlight testing.
5. For production: Advanced App Clip Experience with that URL prefix, title,
   and image; set `MAKON3D_APPLE_APP_STORE_ID` on the backend so the
   `/s/:token` page shows the Safari App Clip card.
6. Flip `MAKON3D_SCAN_CLIP_INVOCATION_BASE` (see above).
